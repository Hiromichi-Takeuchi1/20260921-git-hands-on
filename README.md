# ひだまり商店街

海の近くにある、少しレトロな架空の商店街の地域ポータルです。

暖かな色と店舗のイラストを見ながら、お店を探し、詳しい情報やおすすめの商品を読むことができます。Git・GitHub の共同開発ハンズオン向けに、約 40 人が別々のファイルで店舗を追加できる構成にしています。掲載する店舗・人物・地名・所在地・商品情報はすべて架空です。

## できること・完成イメージ

- 商店街の紹介、6 店舗のカード、商店街のお知らせを表示します。
- 店名・紹介文の検索とカテゴリの絞り込みを組み合わせられます。該当なしの案内も表示します。
- 店舗カードから、営業時間・定休日・所在地・おすすめ商品と価格を載せた詳細ページへ移動します。
- PC とスマートフォンの幅に対応しています。
- 店舗は `src/shops/` の **1 店舗 1 JSON ファイル**で管理します。共通の店舗一覧ファイルへの追記は不要です。
- 画像はリポジトリ内の SVG を使います。画像を省略した店舗には共通イラストを表示します。

HTML・CSS・JavaScript で構成しています。**参加者の PC に Node.js・npm は不要で、サーバーの起動やビルドも不要です。** バックエンド、データベース、認証、外部 API は使いません。お気に入りや並び替えなどは、[演習用 Issue 案](docs/exercises.md)から追加できます。

## ローカルで開く

参加者が用意するのは Git、エディタ、ブラウザです。

1. リポジトリを clone します。初回の手順は **[CONTRIBUTING.md](CONTRIBUTING.md)** を参照してください。
2. clone したフォルダの **`index.html` をダブルクリック**してブラウザで開きます。ブラウザの「ファイルを開く」から選んでも構いません。
3. 最初は同梱された 6 店舗の見本が表示されます。検索・カテゴリ絞り込み・詳細ページを操作できます。

**店舗 JSON を追加・編集したとき、または他の人の変更を取り込んだとき：**

1. トップページ上部の **「店舗データを読み込む」**を押します。
2. ファイル選択画面で `src/shops/` を開き、**その中の JSON をすべて選択**します。Windows は `Ctrl+A`、Mac は `Command+A` で全選択できます。`templates/` のひな形は選びません。
3. 読み込み結果を確認します。エラーが出たら表示されたファイル・項目を直し、もう一度すべて選択します。
4. 一覧から対象の店舗の詳細を開き、変更内容を確認します。

ブラウザは、HTML を直接開いた状態では隣のフォルダを自動で読み取れません。そのため、店舗の確認時だけファイルを選びます。**JSON を保存した後は、再読込だけでなく、再度「店舗データを読み込む」から選び直してください。** 選んだ時点の内容が表示され、詳細ページと一覧への戻りにも引き継がれます。データはブラウザ内で扱い、外部には送信しません。

HTML・CSS・JavaScript（お知らせを含む）の編集は、保存してブラウザを再読込すると反映されます。店舗 JSON の内容が想定と違うときは、最新のファイルを選び直してください。

## 自分のお店を追加する

### 1. 自分専用の店舗ファイルを作る

他の人と重複しない ID を決めます。**半角小文字の英数字とハイフン**だけを使い、英数字で始めて終えてください。ハイフンは連続させません。例として、参加者番号を付けた `p01-nami-cafe` を使います。自分の番号や名前に置き換えてください。

```sh
cp templates/shop-template.json src/shops/p01-nami-cafe.json
```

エディタ上のコピーと名前の変更でも構いません。`templates/` のひな形を直接変更せず、`src/shops/` にコピーします。

### 2. 内容を編集する

コピーした JSON の `id` を、拡張子 `.json` を除いたファイル名と一致させます。店舗名、説明、営業時間、おすすめ商品などを、自分の架空のお店の情報に書き換えます。

| 項目 | 入力内容 |
| --- | --- |
| `id` | 重複しない店舗 ID。ファイル名と一致させる |
| `name` | 店名 |
| `category` | 下表のカテゴリ ID のいずれか |
| `tagline` | 短いキャッチコピー |
| `description` | お店の紹介文。店名とともに検索対象になる |
| `hours` | 営業時間（例：`10:00〜18:00`） |
| `closed` | 定休日（例：`毎週水曜日`） |
| `address` | 商店街内の架空の所在地（例：`ひだまり商店街 こもれび通り 8 番`） |
| `products` | 1 件以上のおすすめ商品・サービス。各項目に `name`、`description`、`price` を入れる |
| `products[].price` | 円単位の 0 以上の整数。`600` のように数値で入力し、`"600円"` とは書かない |
| `image` | 任意。画像のパス。画像なしなら `""` にするか、項目を省略する |
| `imageAlt` | 画像を指定する場合に必須。画像の内容を伝える代替テキスト |

| カテゴリ ID | 内容 |
| --- | --- |
| `food` | 飲食店 |
| `cafe` | 喫茶店 |
| `books` | 書店 |
| `goods` | 雑貨店 |
| `flowers` | 花屋 |

JSON はキーと文字列を半角のダブルクォートで囲み、最後の項目の後ろにカンマを付けません。コメントは書けません。既存店舗を見本にできますが、元の店舗の ID をコピーしたままにしないでください。

### 3. 画像を付ける（任意）

自分で用意した SVG などを `images/shops/p01-nami-cafe.svg` に追加し、JSON に次のように書きます。

```json
"image": "images/shops/p01-nami-cafe.svg",
"imageAlt": "青いひさしと小さなテラスがある喫茶店のイラスト"
```

先頭の `/` や外部 URL を付けず、リポジトリ内の画像を指定してください。画像の権利を確認し、実在の個人情報を含めないでください。

**画像なしで追加する場合は `"image": ""` のままで完成です。** `imageAlt` も空欄で構いません。共通の代替画像が自動で表示されるため、SVG の作成や共通コードの変更は必要ありません。

### 4. 確認する

`index.html` を開き、「店舗データを読み込む」から `src/shops/` 内の JSON をすべて選びます。エラーがないこと、一覧・検索・カテゴリ絞り込みで自分のお店が見つかること、詳細ページで内容が読めることを確認します。詳細は一覧のカードから開いてください。

店舗を編集するのは JSON だけです。`src/data/shop-data.js` は同梱の見本なので、店舗追加に合わせて編集・コミットする必要はありません。新しい店舗を取り込んで clone し直した場合も、JSON をすべて選ぶと最新の全店舗を確認できます。公開時には GitHub Actions が全 JSON を集約するため、公開サイトの利用者によるファイル選択は不要です。

共有ファイルを変更せず、店舗 JSON 1 個（画像を使う場合は画像も）だけで追加できます。共通の CSS や機能を変更する場合は、店舗追加とは別の PR にするとレビューしやすくなります。

## データ検証とビルド

参加者は、ブラウザで JSON を読み込んだときの検証結果を確認します。必須項目、カテゴリ、ID・ファイル名のルールと一致、ID 重複、商品の形式や価格などを検証します。エラーに表示されるファイル名と項目を直し、ファイルを選び直してください。画像を追加した場合は、実際に表示されることも確認します。

PR を送ると GitHub Actions の **Validate and build** が全店舗の検証と公開用ビルドを行います。画像ファイルの存在も CI で確認します。`pull_request` イベントを使用し、fork からの PR に秘密情報は必要ありません。GitHub 側で Node.js を用意するため、参加者の PC へのインストールは不要です。

講師や共通処理の開発者が手元でも実行したい場合のみ、Node.js 22 以上を用意し、次のコマンドを使えます。追加パッケージのインストールは不要です。

```sh
node scripts/validate-shops.mjs
node --test scripts/test-validation.mjs
node scripts/build.mjs
```

ビルドは検証後に全店舗を集約し、公開用の HTML・CSS・JavaScript・画像を `dist/` に出力します。`dist/index.html` を直接開いてビルド結果を確認できます。`dist/` はコミットしません。通常の店舗追加・表示確認では、この作業は不要です。

## GitHub Pages へ公開する（講師向け）

この教材の作成時点では、リポジトリの作成やサイトの公開は行っていません。公開するときは講師が次の設定を行います。

1. GitHub に **public** リポジトリを用意し、このコードを push します。既定ブランチを `main` にします。
2. 下記の置換表を使い、`CONTRIBUTING.md` のリポジトリ情報を実際の情報に置き換えます。
3. **Settings → Actions → General** で GitHub Actions と、このリポジトリで使う公式 Actions を利用できるようにします。fork からの初回 PR の workflow は、GitHub の設定により講師の実行承認が必要になることがあります。
4. **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
5. **Actions → Deploy GitHub Pages → Run workflow** を開き、ブランチ **main** を選んで手動実行します。全店舗の検証・集約・ビルドの成功後に `dist/` が公開されます。
6. workflow の結果か Settings → Pages に表示される URL を開き、一覧・詳細・画像を確認します。

公開 URL の例は `https://INSTRUCTOR_ACCOUNT.github.io/REPOSITORY_NAME/` です。リンク・画像・スクリプトは相対パスで扱うため、リポジトリ名のサブディレクトリ配下でも表示できます。公開サイトでは `shop.html?id=店舗ID` を直接開いても動作します。リポジトリ名を変えても、ソース内の固定 URL の変更は不要です。

この workflow は **手動実行のみ**で、`main` 以外からのデプロイは行いません。PR 作成やマージだけでは公開されないので、更新を公開したいときは手順 5 を再実行してください。`gh-pages` ブランチを作ったり、`dist/` をコミットしたりする必要はありません。公開 workflow のみ GitHub 標準の Pages 用権限を使用し、追加の秘密情報は不要です。設定の参考：[GitHub Pages のカスタム workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

### 講師が事前に決める項目

| 表記 | 置き換える内容 |
| --- | --- |
| `INSTRUCTOR_ACCOUNT` | 元リポジトリの所有者の GitHub アカウントまたは Organization |
| `REPOSITORY_NAME` | 元リポジトリ名 |
| `YOUR_ACCOUNT` | 各参加者自身の GitHub アカウント（参加者が置き換える） |
| `p01` | 各参加者の番号または重複しない短い識別子 |

40 人分の ID の接頭辞と Issue の担当を決めておくと、店舗追加が衝突しにくくなります。レビュー担当とマージ担当も決めてください。必要に応じて `main` の保護ルールを設定し、PR と **Validate and build** の成功をマージ条件にします。fork が許可されていることと、参加者が Issue・PR を作成できることも事前に確認してください。公開教材の再利用方針に応じて、講師が適切なライセンスを選んで追加してください。
